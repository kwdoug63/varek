# VAREK generic sector policy — CYBERSECURITY
# ------------------------------------------------------------------------------
# For an autonomous SOC / detection-and-response agent: reading telemetry and
# logs, triaging alerts, quarantining artifacts, querying a local search tier.
# A detection agent READS widely and WRITES narrowly — it must never gain a
# shell, load kernel code, or reach the systems it monitors.
#
# Posture: DEFAULT-DENY. Deny rules that carve holes out of an allowed tree come
# first. File rules match the RESOLVED canonical path (v1.12).
#
# Replace example paths/hosts with your deployment's real locations.
# v1.16: write the Warden's verdict stream outside every path this policy
# allows (e.g. 2> /var/log/varek/verdicts.log). The Warden refuses to start
# when the agent could open its own stream; /tmp/varek/ below is the agent's
# scratch space, so a log there is refused. Check a deployment with
#   tools/varek_preflight.sh <policy> --log <path> [--sign-key <key>] --run
# ------------------------------------------------------------------------------

# v1.13: `readonly` (= access=ro -O_CREAT -O_TRUNC) makes a rule admit reads
# only. Through v1.12 a path rule admitted every open flag, so the rules marked
# "(read)" below, and the loader rules, also admitted writes by the (root)
# agent. /etc/ld.so.cache is allowed BEFORE `deny path /etc/`: first match
# wins, and in the v1.12 ordering that allow could never fire. Check any
# policy with:  tools/vdp_check <policy> lint
#
# `require warden 1.13` made a v1.12 Warden refuse this file (its parser
# would otherwise ignore `readonly` and admit writes).
#
# v1.14: path and exec rules take a matcher (exact, prefix, suffix, contains,
# glob) before the constant; without one, a path rule is a prefix, as before.
# The block of v1.14 rules below denies key material and credentials wherever
# they appear under an allowed tree, which a prefix rule could not express.
# Matching is on the resolved path's name, byte for byte. Through v1.20.0 these
# rules were case-sensitive and matched the exact name only, so server.PEM,
# x.pem.bak and an id_rsa outside a .ssh directory were allowed; from v1.21
# they spell each letter as a class of both cases and also match a name that
# continues after the extension with a dot or a ~ (see the rules). The
# agent cannot rename files or create links (those syscalls are refused when
# the Warden enforces), so it cannot give an existing file a name these rules
# miss; files it creates in its own scratch space are covered by the same rules.
#
# `require warden 1.14` makes an older Warden refuse this file.
require warden 1.14

# --- Denied even under an allowed tree (evaluated first) ----------------------
allow path /etc/ld.so.cache readonly            # loader cache: read
deny  path /var/log/varek/                 # the agent's own audit trail is not agent-writable
deny  path /etc/shadow                     # never
deny  path /etc/ssh/                        # no host key or SSH config access
deny  path /root/

# --- v1.14: hazards anywhere under an allowed tree (evaluated early) ----------
# The bounded string fragment matches on more than a prefix, so these rules
# reach into every tree the agent is allowed below, including its scratch space.
# v1.21: each letter below is a class of both cases ([pP]), so these match a
# name in any case. A name continuing after the extension with a dot or a ~
# (x.pem.bak, x.key~) matches too; other extensions of the name (serverpem,
# x_pem, j.pemberton.json) do not.
deny  path glob /**/*.[pP][eE][mM]        # private keys and certificates (x.pem, x.PEM)
deny  path glob /**/*.[pP][eE][mM].*      # ... and copies (x.pem.bak, x.PEM.orig)
deny  path glob /**/*.[pP][eE][mM]~       # ... and editor backups (x.pem~)
deny  path glob /**/*.[kK][eE][yY]        # private keys (x.key, x.KEY)
deny  path glob /**/*.[kK][eE][yY].*      # ... and copies (x.key.orig)
deny  path glob /**/*.[kK][eE][yY]~
deny  path glob /**/.[eE][nN][vV]         # dotenv credential files, at any depth
deny  path glob /**/.[eE][nN][vV].*       # ... and their variants (.env.local, .ENV.production)
deny  path glob /**/.[eE][nN][vV]~
deny  path glob /**/.[sS][sS][hH]*        # SSH keys and configuration: the directory (and .ssh-old, ...),
deny  path glob /**/.[sS][sS][hH]*/**     # ... and everything in it, anywhere
deny  path glob /**/[iI][dD]_[rR][sS][aA]*          # SSH private keys wherever they sit, not only
deny  path glob /**/[iI][dD]_[dD][sS][aA]*          # under .ssh (id_rsa, id_rsa.bak, id_ecdsa_sk,
deny  path glob /**/[iI][dD]_[eE][cC][dD][sS][aA]*       # id_ed25519, ...; not a name with a prefix
                                            # such as old_id_rsa)
deny  path glob /**/[iI][dD]_[eE][dD]25519*

# --- Files the agent may reach ------------------------------------------------
allow path /var/log/ readonly                   # system + application logs (read for detection)
allow path /var/lib/varek/quarantine/      # where suspicious artifacts are isolated
allow path /var/lib/detection/rules/ readonly   # YARA / Sigma rule sets (read)
allow path /tmp/varek/                      # scratch workspace
allow path /usr/lib/ readonly                   # loader / shared libraries: read, never write
allow path /usr/lib64/ readonly                 # shared libraries on RHEL, Fedora and Amazon Linux (/lib64 -> /usr/lib64)
allow path /lib/ readonly                       # loader / shared libraries: read, never write
allow path /lib64/ readonly                     # loader / shared libraries: read, never write

# --- Programs the agent may launch --------------------------------------------
allow exec /usr/bin/python3
allow exec /usr/bin/yara
# NOTE: no shell. /bin/sh and /bin/bash are intentionally NOT allowed — a
# detection agent that can spawn a shell is a detection agent that can be lived
# off. Any un-listed exec target is denied.

# --- Network the agent may reach (v1.21: decided connections) ---------------
# These lines take effect from v1.21. The Warden decides each connect against
# them, dials an allowed destination itself and hands the agent the connected
# socket; the connection is recorded like a file open. Through v1.20.0 every
# connect was refused, whatever these lines said. A host rule matches the
# numeric address dialed (a.b.c.d:port, [IPv6]:port or unix:/path); host
# names are not matched until v1.21 stage 2. VAREK decides where the agent may
# connect; what it sends there is for the service, or an egress proxy or DLP
# tool in front of it.
allow host 127.0.0.1:9200                  # v1.21: local search / SIEM tier (e.g. Elasticsearch)
allow host 127.0.0.1:8686                  # v1.21: local detection API
# No egress to the monitored estate: the agent observes, it does not connect out.
