# VAREK generic sector policy — HEALTHCARE
# ------------------------------------------------------------------------------
# For an autonomous agent operating inside a clinical / health-operations
# workflow (drafting orders, updating records, routing prior authorizations,
# handling protected health information (PHI) in the electronic health record
# (EHR)).
#
# Posture: DEFAULT-DENY. Any action not matched by an allow rule below returns
# UNKNOWN and fails closed. Rules are evaluated top to bottom; the first match
# wins, so the deny rules that narrow an allowed prefix come FIRST. File rules
# match the RESOLVED canonical path (v1.12), so `..`, symlinks, and /proc/self
# cannot smuggle a denied object past an allow prefix.
#
# Replace the example paths/hosts with your deployment's real locations. This is
# a starting allowlist, not a finished authorization — tighten per workflow.
# v1.16: write the Warden's verdict stream outside every path this policy
# allows (e.g. 2> /var/log/varek/verdicts.log). The Warden refuses to start
# when the agent could open its own stream; /tmp/varek/ below is the agent's
# scratch space, so a log there is refused. Check a deployment with
#   tools/varek_preflight.sh <policy> --log <path> [--sign-key <key>] --run
# ------------------------------------------------------------------------------

# v1.13: `readonly` (= access=ro -O_CREAT -O_TRUNC) makes a rule admit reads
# only. Through v1.12 a path rule admitted every open flag, so the rules marked
# "(read)" below, and the loader rules, also admitted writes by the (root)
# agent. /etc/ld.so.cache is allowed BEFORE `deny path /etc/`: first match
# wins, and in the v1.12 ordering that allow could never fire. Check any
# policy with:  tools/vdp_check <policy> lint
#
# `require warden 1.13` made a v1.12 Warden refuse this file (its parser
# would otherwise ignore `readonly` and admit writes).
#
# v1.14: path and exec rules take a matcher (exact, prefix, suffix, contains,
# glob) before the constant; without one, a path rule is a prefix, as before.
# The block of v1.14 rules below denies key material and credentials wherever
# they appear under an allowed tree, which a prefix rule could not express.
# Matching is on the resolved path's name, byte for byte. Through v1.20.0 these
# rules were case-sensitive and matched the exact name only, so server.PEM,
# x.pem.bak and an id_rsa outside a .ssh directory were allowed; from v1.21
# they spell each letter as a class of both cases and also match a name that
# continues after the extension with a dot or a ~ (see the rules). The
# agent cannot create links (those syscalls are refused when the Warden
# enforces), and a rename is decided on both of its names (from v1.41, under
# `require warden 1.29`; before, refused), so it cannot give an existing file
# a name these rules miss; files it creates in its own scratch space are
# covered by the same rules.
#
# `require warden 1.27` (v1.40): an older Warden refuses this file. From
# 1.27 the exec rules below decide every launch after the agent's own
# (held by Landlock: a program not named is refused), and every directory
# this file lets the agent write is mounted noexec for the run (nothing in it
# can be launched or mapped executable). Each such directory must exist when
# the run starts, and the agent's program and its standard input must not be
# in one. Under 1.14 every launch after the agent's own was refused,
# whatever these rules said.
#
# `require warden 1.29` (v1.41; v1.40 said 1.27):
#   * Files are opened as the agent's own user and groups, not as root: a
#     directory below that the agent may write must also be writable by the
#     agent's user (`varek run` runs it as nobody unless told otherwise), or
#     the write fails with the kernel's EACCES, recorded.
#   * A change by name in a directory the agent may write (remove, rename,
#     make a directory, change a mode or a time, truncate) is decided as a
#     write on every name it touches, and carried out as the agent; before,
#     each was refused. Removal is decided as truncation is: a rule that lets
#     the agent rewrite a file lets it remove it. Links stay refused.
#   * The legacy stat(2) and lstat(2) are decided like a read-only open:
#     a program built against a glibc before 2.33, or against musl, finds
#     its files with them (a Python from python-build-standalone, which uv
#     installs, could not start under 1.27).
require warden 1.29

# --- Denied even though they sit under an allowed tree (evaluated first) ------
deny  path /var/lib/ehr/audit/            # audit trail is append-only to the system, never the agent
deny  path glob /var/lib/ehr/records/[dD][eE][cC][eE][aA][sS][eE][dD]     # decedent records: separate legal-hold
deny  path glob /var/lib/ehr/records/[dD][eE][cC][eE][aA][sS][eE][dD]/**  # handling (v1.21: any case)
allow path /etc/ld.so.cache readonly            # loader cache: read
# v1.40: what the loader, the C library and Python read under /etc as any
# program starts (most need not exist); read-only, nothing secret
allow path exact /etc/ld.so.preload readonly     # the loader: libraries to preload (usually absent)
allow path exact /etc/locale.alias readonly      # the C library's locale names (Debian links /usr/share/locale/locale.alias here)
allow path exact /etc/localtime readonly         # the C library's time zone (Amazon Linux 2023's Python reads it at start)
allow path glob /etc/python3*/sitecustomize.py readonly   # Debian's Python (sitecustomize.py links here)
allow path glob /etc/alternatives/python3* readonly   # python3 -> /etc/alternatives/python3 -> the program (Debian, RHEL)
deny  path /etc/                          # no system configuration
deny  path /root/                         # no operator home

# --- v1.14: hazards anywhere under an allowed tree (evaluated early) ----------
# The bounded string fragment matches on more than a prefix, so these rules
# reach into every tree the agent is allowed below, including its scratch space.
# v1.21: each letter below is a class of both cases ([pP]), so these match a
# name in any case. A name continuing after the extension with a dot or a ~
# (x.pem.bak, x.key~) matches too; other extensions of the name (serverpem,
# x_pem, j.pemberton.json) do not.
deny  path glob /**/*.[pP][eE][mM]        # private keys and certificates (x.pem, x.PEM)
deny  path glob /**/*.[pP][eE][mM].*      # ... and copies (x.pem.bak, x.PEM.orig)
deny  path glob /**/*.[pP][eE][mM]~       # ... and editor backups (x.pem~)
deny  path glob /**/*.[kK][eE][yY]        # private keys (x.key, x.KEY)
deny  path glob /**/*.[kK][eE][yY].*      # ... and copies (x.key.orig)
deny  path glob /**/*.[kK][eE][yY]~
deny  path glob /**/.[eE][nN][vV]         # dotenv credential files, at any depth
deny  path glob /**/.[eE][nN][vV].*       # ... and their variants (.env.local, .ENV.production)
deny  path glob /**/.[eE][nN][vV]~
deny  path glob /**/.[sS][sS][hH]*        # SSH keys and configuration: the directory (and .ssh-old, ...),
deny  path glob /**/.[sS][sS][hH]*/**     # ... and everything in it, anywhere
deny  path glob /**/[iI][dD]_[rR][sS][aA]*          # SSH private keys wherever they sit, not only
deny  path glob /**/[iI][dD]_[dD][sS][aA]*          # under .ssh (id_rsa, id_rsa.bak, id_ecdsa_sk,
deny  path glob /**/[iI][dD]_[eE][cC][dD][sS][aA]*       # id_ed25519, ...; not a name with a prefix
                                            # such as old_id_rsa)
deny  path glob /**/[iI][dD]_[eE][dD]25519*
deny  path glob /var/lib/ehr/records/**/[pP][sS][yY][cC][hH][oO][tT][hH][eE][rR][aA][pP][yY]     # psychotherapy notes need separate patient
deny  path glob /var/lib/ehr/records/**/[pP][sS][yY][cC][hH][oO][tT][hH][eE][rR][aA][pP][yY]/**  # authorization: the directory and its files, at any depth

# --- Files the agent may reach ------------------------------------------------
allow path /var/lib/ehr/records/          # patient record store (read/update per workflow)
allow path /var/spool/hl7/outbound/       # HL7 / FHIR messages the agent composes
allow path /var/lib/ehr/orders/draft/     # order drafts staged for clinician sign-off
allow path /tmp/varek/                     # scratch workspace
allow path /usr/lib/ readonly                   # loader / shared libraries
allow path /usr/lib64/ readonly                 # shared libraries on RHEL, Fedora and Amazon Linux (/lib64 -> /usr/lib64)
allow path /lib/ readonly                       # loader / shared libraries: read, never write
allow path /lib64/ readonly                     # loader / shared libraries: read, never write
allow path /usr/share/ readonly                  # shared OS data (time zones, locale): read, never write
# v1.40: what the C library and Python read as they start, most of it files
# that need not exist; without these every run began with some 19 refusals,
# noise to an alerting rule (docs/security/v1.39-security-operations.md)
allow path exact /proc/sys/vm/overcommit_memory readonly   # the C library's allocator
allow path glob /usr/bin/python3* readonly       # Python reads its own program and links to find its home
allow path exact /usr/bin/pyvenv.cfg readonly    # Python: is this a virtual environment (absent)
allow path exact /usr/pyvenv.cfg readonly
allow path exact /usr/bin/pybuilddir.txt readonly    # Python: a build tree's marker (absent)
allow path exact /usr/bin/lib readonly          # Python: where a build tree's library would be (absent: decided
allow path /usr/bin/lib/ readonly                # where the lookup stops, this name)
allow path exact /usr/bin/Modules readonly      # Python 3.12: a build tree's other marker,
allow path /usr/bin/Modules/ readonly            # Modules/Setup.local (absent)
allow path exact /usr/bin/lib64 readonly        # Python on RHEL and Amazon Linux (its library in lib64):
allow path /usr/bin/lib64/ readonly              # os.py, os.pyc, lib-dynload looked for here first (absent)
allow path /usr/local/lib/ readonly              # packages installed for every user (pip without --user)
allow path /usr/local/lib64/ readonly            # ... on RHEL, Fedora and Amazon Linux
# v1.41: the same for a Python installed in /usr/local (a container image's,
# or python-build-standalone's), and what such a Python reads of its own
# process as it starts
allow path glob /usr/local/bin/python3* readonly # its program and links
allow path exact /usr/local/bin/pyvenv.cfg readonly   # a virtual environment? (absent)
allow path exact /usr/local/pyvenv.cfg readonly
allow path exact /usr/local/bin/pybuilddir.txt readonly   # a build tree's marker (absent)
allow path exact /usr/local/bin/lib readonly     # a build tree's library (absent)
allow path /usr/local/bin/lib/ readonly
allow path exact /usr/local/bin/Modules readonly # a build tree's other marker (absent)
allow path /usr/local/bin/Modules/ readonly
allow path exact /usr/local/bin/lib64 readonly   # its library in lib64 (absent)
allow path /usr/local/bin/lib64/ readonly
allow path exact /proc/self/exe readonly         # its own program, to find its home
allow path exact /proc/self/maps readonly        # its own memory map
allow path exact /dev/urandom readonly           # random bytes
allow path exact /tmp/varek readonly             # the scratch directory itself (its rule above covers what is in it)

# --- Programs the agent may launch --------------------------------------------
# python3 is a general-purpose interpreter: the agent may start Python
# processes on any script it can read (the file and network rules still hold).
allow exec /usr/bin/python3

# --- Network the agent may reach (v1.21: decided connections) ---------------
# These lines take effect from v1.21. The Warden decides each connect against
# them, dials an allowed destination itself and hands the agent the connected
# socket; the connection is recorded like a file open. Through v1.20.0 every
# connect was refused, whatever these lines said. A host rule matches the
# numeric address dialed (a.b.c.d:port, [IPv6]:port or unix:/path); host
# names are not matched until v1.21 stage 2. VAREK decides where the agent may
# connect; what it sends there is for the service, or an egress proxy or DLP
# tool in front of it.
allow host 127.0.0.1:8443                  # v1.21: local FHIR / interoperability gateway
# No external egress: PHI does not leave the host. Any un-listed host is denied.
